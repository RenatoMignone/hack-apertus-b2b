03

Prepare one company case

Each case pins a domain profile and memory snapshot. Research branches can run independently where identity and permissions are clear; clarification pauses only the dependent work.

Clarification loop: ambiguous company, intended application or exclusion → ask one focused question → wait on the affected branch → store the answer against the correct revision → resume. No answer means unknown.
Research branches · all results retain source and scope
Company profile + query plan refine expertise retrieval; independent branches may proceed with partial context
If support is missing: fetch neighboring evidence, revise queries or ask a question; stop at configured budgets

↺ Supplemental retrieval returns to ranking/support checks (C11–C12). Unresolved gaps remain limitations when the budget ends.

Separate three quantities: match relevance (fit to this need), case similarity (fit to a previous case), and evidence strength (support, dates, conflicts). None is automatically a probability of success. A reachable URL alone does not establish semantic support.

05

Write, validate, review, export

The report structure stays fixed. New factual assertions require evidence retrieval; formatting and emphasis changes reuse the accepted pack.

Presentation-only edit
“Make this shorter” → new result revision → reuse evidence → rewrite → validate → review → regenerate affected exports.
Research/focus edit
“Exclude this unit; focus on sensors” → revised intent/query plan → bounded retrieval + validation → new pack → regenerate report. Old exports become superseded.

Never publish the generated report into the shared corpus as its own factual source. Reviewed eligible case memory goes through ingestion validation/publication. Sending a deck and arranging meetings remain human actions.

06

Change the domain, keep the engine

Medicine/medtech is the current configured pilot. A future robotics or manufacturing profile supplies new sources, concepts and evaluation cases; it does not require rewriting the evidence or orchestration pipeline.

Stable core

Domain-independent engine

Collection interfaces → parsers → documents/evidence → claims/entities → chunk/index APIs → case intent → retrieval → validation → evidence pack → report/revisions/export.

No hardcoded diabetes terms, institutional domains or clinical assumptions in core flow.
Versioned configuration

Domain profile

Source registry/families + geography/languages + taxonomy/aliases + optional entity/predicate extensions + domain prompts/rules + ranking settings + gold examples + report terminology/branding.

Run pins profile, schema, taxonomy, snapshot, embedding/index and model/prompt versions.
New profile / data change

Identify affected stages

New sources? Parser change? Taxonomy change? Different embedding space?

Reprocess selectively

Reuse raw bytes and compatible evidence. Reclassify, rechunk or re-embed only as required.

Build & evaluate in staging

Check lineage, access, vectors, coverage and domain-specific expected results.

Publish new snapshot

Switch active pointer after validation; retain rollback where permitted. Existing runs stay pinned.

08

Data ownership and persistence

Selected design: PostgreSQL + pgvector, LangGraph PostgreSQL checkpoints and self-hosted Langfuse. Logical contracts stay in Phase 1; focused data specifications own the physical implementation. Nothing here is deployed yet.

Application authority

PostgreSQL navigator

corpus: sources, document versions, exact evidence, entities, claims and snapshots.
taxonomy: profiles, concepts, aliases and assignments.
retrieval: chunks, embeddings and lexical projections.
cases: inputs, runs, packs, reviews and exports.
ops: frontier, jobs, attempts and publication.

Raw/normalized bytes and rendered outputs live in controlled artifact storage, referenced by IDs and hashes.
Workflow persistence

LangGraph database

Framework-owned PostgreSQL checkpoints keep thread state, pending questions and versioned references. Business history remains in navigator.

Resume idempotently after a crash. No distributed transaction across case writes, checkpoints and artifact storage.
Observability

Local Langfuse stack

Web/worker, its PostgreSQL database, ClickHouse, Redis/Valkey and S3-compatible storage. Track allowed metadata, model/retrieval timings, errors and evaluations.

Masked payloads; case/run/snapshot correlations. Traces are not evidence. Tracing outage does not block a case.
