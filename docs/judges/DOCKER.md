# Docker Compose setup

The repository has three Compose definitions:

- [Data stack](../../src/backend/deploy/compose.yaml): PostgreSQL/pgvector, MinIO
  and bucket/policy initialization; optional local tracing services.
- [Runtime](../../src/backend/deploy/runtime.compose.yaml): API and worker
  containers using an existing data network.
- [Search sidecar](../../src/backend/deploy/search.compose.yaml): optional private
  SearXNG; Crawl4AI needs its separate interpreter/environment.

There is currently **no frontend Compose service**. The simplest documented live
layout uses Compose for data services and host processes for API/worker/frontend.
The optional runtime image needs additional provisioning for hosted encoder
dependencies, mounted tokenizers/configuration and optional crawler/model assets.
These instructions are a setup guide, not a recorded successful image build.

## 1. Prerequisites

Use Docker with Compose v2, Python 3.12–3.14 and Node 22.18+/npm.
On Windows enable Docker Desktop's Linux engine/WSL2. All commands start at the
repository root. Initial package/image downloads need a network connection.
Existing deployments should reuse their private settings; bootstrap below is
only for a **new local data stack**.

PowerShell:

```powershell
py -3.13 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r src/backend/requirements.lock
.\.venv\Scripts\python.exe -m pip install --no-deps -e src/backend
.\.venv\Scripts\navigator.exe host-init
docker compose -f src/backend/deploy/compose.yaml up -d postgres minio storage-init
```

Bash:

```bash
python3.13 -m venv .venv
source .venv/bin/activate
python -m pip install -r src/backend/requirements.lock
python -m pip install --no-deps -e src/backend
navigator host-init
docker compose -f src/backend/deploy/compose.yaml up -d postgres minio storage-init
```

Host initialization reads [images.lock.json](../../src/backend/deploy/images.lock.json)
and generates ignored `src/backend/deploy/.env`; it refuses to overwrite it.
Compose automatically reads that file beside its data-stack definition.
PostgreSQL and MinIO bind host loopback ports 5432 and 9000 (console 9001).
Check that the PostgreSQL service is healthy and `storage-init` has exited
successfully before continuing:

```text
docker compose -f src/backend/deploy/compose.yaml ps -a
docker compose -f src/backend/deploy/compose.yaml logs --tail 50 storage-init
```

Keep logs private if they include diagnostic data. Do not remove shared volumes
or reinitialize a teammate's existing stack to follow these steps.

## 2. Initialize the new database

After activating the virtualenv, use the generated maintainer environment:

```text
navigator --env-file src/backend/deploy/.env db-migrate
navigator --env-file src/backend/deploy/.env checkpoint-setup
```

On PowerShell, use `.\.venv\Scripts\navigator.exe` if the environment is not
activated. These are explicit owner operations for a new stack. For shared-host
upgrades, coordinate the documented backup/window and inspect
[migration receipts](../team/MIGRATION_STATUS.md); never run them implicitly.
Changing env-file passwords does not rotate existing database credentials.

This creates schema and checkpoint tables, **not a usable institutional corpus**.

## 3. Prepare a real runtime environment

Create an ignored root `.env` from [.env.example](../../.env.example), without
overwriting an existing private file. The maintenance environment generated by
`host-init` is not an API/worker credential bundle.

The maintainer must provision:

1. An ordinary application principal/namespace with the intended public-read
   grants and owned-case writes.
2. An authorized domain profile, taxonomy and compatible corpus release or live
   capture configuration. An empty schema is not enough.
3. Separate checkpoint credentials and source/export artifact access.
4. Operator-token SHA-256 bindings in `RUNTIME_AUTH_BINDINGS`; the raw token goes
   to the operator's Connect screen.
5. Apertus access with `LLM_NAME`, `LLM_BASE_URL`, `LLM_API_KEY`.
6. Matching encoder configuration and tokenizer/model assets.

For host-run API/worker against this new local stack, use host addresses
`127.0.0.1:5432` and `http://127.0.0.1:9000`. The root example instead uses
shared-host tunnel ports 15432/19000; change them to the selected placement.
Both application and checkpoint DBs use PostgreSQL's port but different access.

For connected HF embeddings install the supplemental lock in the host backend
environment:

```text
python -m pip install -r src/backend/requirements.hosted.lock
```

Provision the pinned tokenizer and verified configuration from
[hosted embedding setup](../data/HOSTED_EMBEDDINGS.md). The encoder configuration
must match the indexed vectors. Startup never downloads these assets or builds
the corpus. Corpus preparation follows the
[ingestion handoff](../data/INGESTION_RETRIEVAL_HANDOFF.md).
A public, redistributable ready-to-use corpus bundle has not been packaged here.

## 4. Run API/worker on the host

This path supports the host's separately installed encoder dependencies/assets.
From the activated virtualenv, with the same private runtime environment:

```text
python -m backend.deploy.check_runtime --env-file .env
python -m backend.deploy.check_runtime --env-file .env --network
navigator-runtime --env-file .env serve --host 127.0.0.1 --port 8000
```

In a second terminal:

```text
navigator-runtime --env-file .env worker
```

Start the [frontend in HTTP mode](QUICKSTART.md#3-provisioned-live-application)
and connect with the operator token. Verify one case through evidence inspection,
review and authenticated PDF download. Readiness checks do not prove full model
availability, runtime writes or research quality.

## 5. Optional API/worker containers

[Runtime Compose](../../src/backend/deploy/runtime.compose.yaml) uses an external
network named `bern-navigator_default` by default, created by the data stack above.
If the data Compose project name is changed, set `NAVIGATOR_NETWORK` to its actual
network name.

Before building, supply an operator-verified digest-pinned Python 3.13 image
through `PYTHON_RUNTIME_IMAGE`. Create a private runtime env using container
addresses: application DB at `postgres:5432/navigator`, checkpoint DB at
`postgres:5432/langgraph`, and artifacts at `http://minio:9000`.
Loopback/tunnel addresses inside a container point to that container.

Set `RUNTIME_ENV_FILE` to the **absolute path** of that private runtime env.
This avoids the Compose file's default `../.env`, which is relative to its own
directory and is not the root application env. Use shell variables for Compose
interpolation; a service's `env_file` does not supply build arguments to Compose.

Bash, after setting real values in your shell:

```bash
export RUNTIME_ENV_FILE="/absolute/path/to/private-runtime.env"
export PYTHON_RUNTIME_IMAGE="python:3.13-slim@sha256:REPLACE_WITH_VERIFIED_DIGEST"
docker compose -f src/backend/deploy/runtime.compose.yaml config --quiet
docker compose -f src/backend/deploy/runtime.compose.yaml up --build -d
```

PowerShell:

```powershell
$env:RUNTIME_ENV_FILE = 'C:/absolute/path/to/private-runtime.env'
$env:PYTHON_RUNTIME_IMAGE = 'python:3.13-slim@sha256:REPLACE_WITH_VERIFIED_DIGEST'
docker compose -f src/backend/deploy/runtime.compose.yaml config --quiet
docker compose -f src/backend/deploy/runtime.compose.yaml up --build -d
```

**Provisioning gap:** the base Dockerfile installs the core lock only. It does
not install the HF tokenizer supplemental lock or local-model dependencies and
does not mount tokenizer/model/configuration assets. Prepare a target-specific
image extension and read-only asset mounts/Compose override before using those
adapters. Worker web research also needs its isolated crawler interpreter and
network access to the search sidecar. A host interpreter path cannot be reused
inside the container. These prerequisites must be satisfied before running the
`up` command for the selected model setup; the shown placeholders are not runnable
image pins.

The API binds host localhost:8000. For external access add an approved HTTPS
entry point and exact origin configuration. The frontend still runs separately.
The supplied report logo/template are packaged; filesystem artifacts use the
shared runtime volume, while corpus artifacts normally use configured S3.

## Optional services and lifecycle

Local tracing, using the data stack's configured observability profile:

```text
docker compose -f src/backend/deploy/compose.yaml --profile observability up -d
```

Provision its private project keys before enabling traces. For SearXNG plus
separate Crawl4AI, follow [web setup](../data/WEB_RESEARCH.md); search Compose is
independent and requires its own private secret. Container networking must be
configured explicitly; host loopback is not shared across services.

Inspect runtime state without printing resolved secrets:

```text
docker compose -f src/backend/deploy/runtime.compose.yaml ps
docker compose -f src/backend/deploy/runtime.compose.yaml logs --tail 50 api worker
```

Use `stop` on the specific Compose project to pause it. Keep persistent data
volumes; do not use `down -v` or global prune commands on a shared installation.
Follow [backup/restore](../data/DEPLOYMENT.md#backup-and-restore) for maintainer
operations. Neither Compose configuration nor connected model access establishes
air-gapped or sovereign deployment.
