# Isolated pipeline reliability receipt

Measured 19 October 2026. No shared-host, retrieval SQL, index, ingestion or migration
changes. Public HTTP/assessment contracts are unchanged.

## Changes

- Pinned domain codes appear in the private interpretation schema. Bounded repair
  identifies missing blocking questions; later answers resolve historical ambiguity.
- Extraction retains explicit general capabilities without inventing absent methods
  or product details. Independent assessment and need-to-capability fit remain gates.
- Draft assessment covers every exact reason and every numbered pack gap. Code
  derives rejection from unsupported findings or missing caveats. Exact references,
  independent assessment and the existing bounded wording rewrite remain mandatory.
- Follow-up retrieval returning identical source records and entity context reuses
  prepared evidence with unresolved gaps. A failed draft with unchanged evidence
  stops. New passages or changed entity context still go through preparation.
- Frontend recovery labels match the actual current-input pack reuse predicate.
  Existing error codes remain visible after reload; tokens remain memory-only.
- Safe optional model receipts identify calls, repairs, durations and usage. Existing
  stage logs provide duration/reuse events without prompts, source text or credentials.

## Measured acceptance

Actual configured Keera Apertus v1.5 70B; real API, restricted application DB role,
LangGraph worker and PostgreSQL checkpoints; fictional named source, synthetic
3-dimensional embeddings and local filesystem artifacts. Web/reranking were not
provisioned. The harness explicitly frames all model tasks as a closed-world
fictional evaluation. No scripted model judgments replace actual responses.

| Scenario | Result | Elapsed |
| --- | --- | --- |
| Clear capability match | Two assessed reasons; review/PDF; wording revision; stale download rejected | 66.738s |
| Vague request → clarification | One answered question; two assessed reasons; review/PDF; stale download rejected | 62.937s |
| Unrelated satellite propulsion | Explicit no-match, zero reason cards | 8.210s |

The first two timings include export and a subsequent wording-only revision.
Across these three scenarios: 23 model calls, one schema repair, zero exhausted
repairs, 38,839 prompt tokens and 7,434 completion tokens.
The original long fictional Helvetic request separately passed interpretation in
9.578s without blocking questions. These are individual observations, not an SLA.

Initial probes failed: fictional-source entailment was confused with real-world
verification, general capabilities were suppressed for missing optional specifics,
and exact caveat text was inconsistently copied. Final checks retain the original
match expectation, preserve fictional qualifications and use numbered gap findings.
The bounded gates rejected invalid intermediate outputs; they were not bypassed.

**304 backend tests passed** on explicitly disposable PostgreSQL, including actual
checkpoint restart/process recovery with scripted providers and SQL timeout
isolation. **26 frontend tests**, TypeScript and production build passed. Existing
pytest deprecation and frontend bundle-size warnings remain.
Browser inspection verified source passages, report versions, selections and reload/
reconnect persistence. The two-page match PDF was rendered and visually inspected.

receipts, generated case JSON and PDFs in ignored `.local/reliability/`.

This does not establish real-corpus recall, shared-host latency, live web quality,
reranking value or deployment isolation. Real checkpoint restart was tested with
scripted providers separately from the continuous actual-model runs. Eric's shared
